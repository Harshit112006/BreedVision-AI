# Problem Statement (revised draft)

Smart India Hackathon SIH25004. This paraphrases the team deck; copy the official
wording from the SIH portal for the submission.

## The problem

India holds the world's largest livestock population (the deck cites 536 million
cattle and buffaloes, 20th Livestock Census; not independently verified here).
Yet breed identity and animal value are both recorded by hand:

- **Breed is judged by eye** by scarce experts, so it is subjective and varies
  between regions.
- **Value is negotiated without reliable reference data**, which disadvantages
  smallholders.
- Wrong or duplicated records distort breeding programmes, insurance claims,
  subsidy allocation and national livestock databases.

## The solution

BreedVision AI lets a field worker photograph an animal and get:

1. A **breed prediction with a calibrated confidence score**, which says so when
   it is unsure rather than guessing.
2. After a few basic inputs (age, milk yield, lactation stage), an **estimated
   value range** with the reasoning shown.
3. A **GPS-tagged record** that works offline and syncs later.
4. A **duplicate-photo flag**, so the same picture is not submitted twice. It
   does not identify individual animals.

## Price estimation: how it must work

A photo identifies the breed; it does not reveal age, yield, lactation or local
demand. So this is an **estimator, not a detector**:

- Breed comes from the model. Age, yield and lactation stage come from the user.
- Until real data exists, output is a **relative value index**, not a price. A
  rupee **range labelled as an estimate**, listing its inputs, would come only
  after a verified source or enough logged sales.
- Base ranges must come from a documented source. Until one is found and
  verified, no price is shown. Inventing per-breed prices would be worse than
  omitting the feature.
- Users may log actual sale prices, which builds the missing dataset over time.

## Price features as built

**`/prices` page**

- **Relative value** calculator. It uses the two significant, measurable
  effects from Kumar et al. (2014, Table 2, overall dairy-cow model): daily milk
  yield and pregnancy. Pregnancy counts as 1.55 litres of daily yield (the ratio
  1114.07 / 719.54). The output is a unitless index in litre-equivalents with a
  ranked breakdown of factors. **It prints no rupee amount**, because the
  source data is from 2010-11, one state, and contains no indigenous breeds.
  Breed is deliberately not part of the index.
- **Sale-price log**: users record real sales (breed, price, date, optional
  yield, age, pregnancy). Stored on the device. A breed's observed median is
  shown only after 5 real sales.
- **Ranking and history**: logged sales ranked by value index, and a quarterly
  median price line.

**Synthetic demo data** (`ml/synthetic/`, generated by
`ml/scripts/make_synthetic_prices.py`): 504 invented sales over 84 months.
Every row is flagged `synthetic`, shown with a "Demo" badge, and excluded from
observed prices. Base price, breed multipliers, inflation, seasonality and noise
are arbitrary; breed multipliers are random draws, not a claim about any breed.
It tests the screens. It cannot validate a price model, because a model fitted
to it only relearns the generating formula.
