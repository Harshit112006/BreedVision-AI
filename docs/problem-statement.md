# Problem Statement (revised draft)

Smart India Hackathon SIH25004. This paraphrases the team deck; copy the official
wording from the SIH portal for the submission.

## The problem

India holds the world's largest livestock population (the deck cites 536 million
cattle and buffaloes, 20th Livestock Census; not independently verified here).
Yet breed identity and animal value are both recorded by hand:

- **Breed is judged by eye** by scarce experts, so it is subjective and varies
  between regions.
- **Value is negotiated without reliable reference data**, which disadvantages
  smallholders.
- Wrong or duplicated records distort breeding programmes, insurance claims,
  subsidy allocation and national livestock databases.

## The solution

BreedVision lets a field worker photograph an animal and get:

1. A **breed prediction with a calibrated confidence score**, which says so when
   it is unsure rather than guessing.
2. After a few basic inputs (age, milk yield, lactation stage), an **estimated
   value range** with the reasoning shown.
3. A **GPS-tagged record** that works offline and syncs later.
4. A **duplicate-photo flag**, so the same picture is not submitted twice. It
   does not identify individual animals.

## Price estimation: how it must work

A photo identifies the breed; it does not reveal age, yield, lactation or local
demand. So this is an **estimator, not a detector**:

- Breed comes from the model. Age, yield and lactation stage come from the user.
- Until real sale data exists, output is an **indicative rupee estimate with a
  range**, labelled as such, listing its inputs and its source. It is built from
  a breed guide's listed prices plus the milk and pregnancy effects
  (`price-reference.md`). It is not a market quote.
- Base ranges come from one documented source for 10 of the 49 breeds. The other
  39 use a general desi-cow range and the page says so; no breed-specific price
  is invented for them.
- Users may log actual sale prices, which builds the missing dataset over time.

## Price features as built

**`/prices` page**

- **Cattle value** estimator ("Find the value of your cattle"). Pick a breed (or
  arrive from an identified result), enter daily milk yield and pregnancy, and it
  shows an indicative rupee value and likely range, with the breakdown and the
  source. Pregnancy counts as 1.55 litres of daily yield (the ratio
  1114.07 / 719.54, Kumar et al. 2014, Table 2); that paper's own 2010-11 rupee
  amounts are not used. Details and limits: `price-reference.md`. The unitless
  relative value index is still used to rank logged sales.
- The sale-price log, ranking, history chart and observed-prices views that
  were built earlier have been **removed from the interface**; only the
  estimator remains.

**Synthetic sales data** (`ml/synthetic/`, generated by
`ml/scripts/make_synthetic_prices.py`): 414 invented sales, Jan 2021 to Sep 2026,
each a random draw around the researched price ranges. Every row is flagged
`synthetic`. It is no longer displayed in the app.
The yearly trend, seasonality and noise are assumptions. It tests the screens. It
cannot validate the estimator, because both share one formula.
